# Domain docs

Use a single context. Before exploring or changing domain behavior, read the repository's root `CONTEXT.md` and any relevant decisions in `docs/adr/`.

If these files do not exist, continue without them. Add glossary entries and ADRs when terms or decisions are settled, not as placeholders.

Use glossary terms consistently in issues, proposals, and tests. If a proposal conflicts with an ADR, name the conflict explicitly instead of silently overriding the decision.
