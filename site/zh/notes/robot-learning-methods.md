## 让学习回答一个特定的问题

机器人可以使用学习的探测器，并且仍然使用经典控制器进行驱动。它还可以使用仿真器的精确状态并学习控制策略。这些是不同的工程决策。询问哪种输入输出映射的指定成本太高、你可以获得哪些数据、哪些错误可以恢复以及如何与更简单的实现进行比较。

对于桌面任务，从在已知重置上成功的脚本序列开始。如果即使在最简单的场景中也失败了，那么添加策略会隐藏基线缺陷。如果它可以在干净的位姿上工作，但在视觉变化下表现不佳，则检测器可以解决困难的部分，而无需更换整个控制器。

## 使用共享任务合同

```text
 observation at t ──▶ policy ──▶ bounded action at t
      ▲                                    │
      │                                    ▼
 observation at t+1 ◀── environment transition
                            ├─ outcome / termination
                            └─ reward (if the task defines one)
```

状态可能包含对象的位姿、摩擦状态或接触历史。观测结果可能仅包含裁剪后的图像和关节角度。如果两个潜在状态看起来相同并且需要不同的操作，则任何无记忆策略都无法仅根据观测结果区分它们。历史记录、新传感器或更安全的后备措施可以使问题得到更好的解决。

| 方法 | 监督 | 优点 | 测试失败 |
| --- | --- | --- | --- |
| 脚本化反馈 | 程序员指定的模型和规则 | 清晰的基线；测试和诊断通常很便宜 | 状态估计或接触假设失败 |
| 行为克隆 | 展示的观察和行动 | 当有足够的演示可用时，直接监督目标 | 小错误使策略脱离了示威 |
| 强化学习 | 环境交互与奖励 | 可以发现不在演示集中的行为 | 利用代理奖励、学习仿真器快捷方式或需要多次尝试 |
| 混合动力 | 规则或计划加上学习的组件 | 限制学习的作用并保留已知的不变量 | 耦合隐藏了第一个错误输入的位置 |

强化学习也可能使用离线数据；该表描述了常见的启动工作流程，而不是严格的定义。情节定义重置和结束条件。奖励是学习者看到的信号，而不是行为有用的证据。一个策略可以在错过任务的同时获得高额代理奖励。

## 实验室：捕捉教导错误行为的奖励

这是一个一步式环境，而不是 RL 训练实施。每个候选解从 0 到 10 中选择一个目的地。目标是 6。设计糟糕的评分标准奖励速度，但没有足够的成本来应对超调。运行代码并将每个奖励下的获胜者与独立定义的任务成功进行比较。

```python
TARGET = 6
DESTINATIONS = range(11)


def succeeds(destination):
    return abs(destination - TARGET) <= 1


def flawed_reward(destination):
    return destination - 0.5 * abs(destination - TARGET)


def task_reward(destination):
    return 2.0 * succeeds(destination) - 0.1 * abs(destination - TARGET)


for label, score in (("flawed", flawed_reward), ("revised", task_reward)):
    winner = max(DESTINATIONS, key=score)
    print(label, "destination", winner, "reward", score(winner), "success", succeeds(winner))

assert max(DESTINATIONS, key=flawed_reward) == 10
assert max(DESTINATIONS, key=task_reward) == 6
```

第一个目标即使在目标之后也鼓励更大的积极目标。在位置 10 时，其奖励为 8，高于目标处的 6。优化器在寻找该解决方案时没有错误。在修改后的奖励中，任务成功更加重要，而准确的位置打破了平局。在真实的实验中，添加针对不安全路线、超时、重复进度信用和不可观察标签的测试，而不是信任这个标量配方。

仅更改有缺陷的奖励中的超调惩罚。高于 6 时，如果系数低于 1，则得分随目的地而增加；当系数等于 1 时，得分持平；高于 1 则降低。在相等时，多个目的地并列获得最佳得分，并且实现的抢七可能会掩盖失败。检查所有最大化器，而不仅仅是一个。

## 将学习工作按发展顺序排列

1. 写下允许的观察、操作空间、控制间隔、重置范围、终止、成功标准和已知的不安全条件。对所有候选策略使用相同的观测约定，除非额外的传感器是实验。
2. 运行随机或恒定命令基线和可解释的专家。报告故障类别。仅拍摄成功试验的演示并不是基准。
3. 对于模仿，审核演示时间，保留整个轨迹或会话，并仅对训练数据进行归一化。对于 RL，检查奖励组件并运行压力测试，其中代理和实际成功可能不一致。
4. 过拟合一小批来检查训练路径，然后使用固定的试验计数和比较预算来评估闭环重置。记录推理时间；策略可能是正确的，但速度太慢。
5. 检查同一重置的最早偏差。在更改架构之前，验证命令扩展、排序、过时输入以及下一个观察是否超出训练分布。

## 练习

策略在模拟中遵循视觉目标，但目标位置意外出现在没有实际传感器等效项的调试张量中。已经证明了什么？

<details>
<summary>检查观察合同</summary>
<p>模拟任务的 Oracle 基线。删除额外的张量，建立有效的估计，或清楚地描述不同的预期传感器。根据实际观察合同进行再培训或重新评估。</p>
</details>

在错过推送后，你的模仿策略很少会恢复。它对专家数据的保留操作错误非常低。什么实验可以区分缺乏恢复数据和错误的输出范围？

<details>
<summary>检查第一个分歧</summary>
<p>通过保存的后处理器驱动已知目标，并首先在仿真器中验证操作语义。然后比较匹配的推出并将代理置于有界模拟恢复状态以查看它是否生成纠正操作。如果表示通过并且仅在演示的轨迹之外缺少校正，请调查覆盖范围。</p>
</details>

## 弘扬什么

当数据和评估回答相同的工程问题时，选择学习。保留更简单的基线，并将奖励、精确的仿真器状态和记录的轨迹视为具有定义限制的证据。
