## 机器人工作需要什么？

你很少单独建造一个完整的机器人。机器人开发人员需要足够的广度来调试与同事的接口，然后深入他们拥有的系统。了解仿真器的菜单比了解机器人为何估计状态、它如何实施限制以及哪些证据表明行为发生了变化要狭窄。另一方面，记住每个控制或机器学习算法并不能替代成功地再现和诊断真实的工作流程。

使用本书作为具有实用退出标准的共同核心。自学作品集展示了你如何思考、实施和验证。它并不证明你可以操作设备、取代受监督的实践或保证为每项机器人工作做好准备。

## 按阶段学习，而不是功能清单

```text
 common core: motion + sensing + planning + software verification
                  |
       choose one working problem / project
                  |
       one specialty in depth + one adjacent interface
                  |
       portfolio review + supervised practice where available
```

一个示例计划是四个方块。它们不是日历上的承诺。如果你无法在不逐行遵循说明的情况下重现工件，请重复一个块。

| 块 | 学习和构建 | 退出标准 |
| --- | --- | --- |
| A：闭环基础知识 | [Python机器人](/zh/notes/robot-loop/)、[测量](/zh/notes/robot-math-and-measurement/)、[框架](/zh/notes/coordinate-frames/)、[运动学](/zh/notes/robot-kinematics/) | 手动预测一个输出，运行夹具，并解释故意错误的单位或符号 |
| B：自主循环 | [控制](/zh/#motion)，[估算](/zh/#sensing)，[规划](/zh/#autonomy) | 对一个传感器错误进行建模，预测路线或控制响应，并描述故障的特征 |
| C：交付和再现性 | [ROS 2](/zh/#ros-2)、[模拟](/zh/#isaac-sim) 和[基础设施](/zh/#infrastructure) | 在全新环境中运行预期配置并使用捕获的跟踪重现一次故障 |
| D：申请项目 | [Rover](/zh/notes/capstone-rover/) 或 [tabletop](/zh/notes/capstone-tabletop/)，加上适当的专业化 | 显示基线、诊断实验、预期结果与观察到的结果以及明确的下一步工作范围 |

对于每个块，在构建或诊断上花费的精力至少与在阅读上花费的精力一样多。保留“下一个问题”，而不是一长串未读主题的无差别列表。示例：“机器人转动时，估算器是否保持世界坐标系点一致？”比“学习更多 SLAM”让下一次课程更好。

## 根据你想做的工作选择深度

| 方向 | 在这里深入了解一下 | 作品集练习 | 超越这个核心的学习 |
| --- | --- | --- | --- |
| 机器人软件/集成 | ROS 2 工作区、接口、时钟、回放、[C++ 端口](/zh/notes/cpp-robot-software/)、CI | 运行新鲜室集成场景并针对时间或 QoS 不匹配提供记录的回归测试 | C++ 所有权和并发性、构建系统、分析、驱动程序和中间件内部结构 |
| 控制/操纵 | 运动学、雅可比行列式、动力学、轨迹极限、抓取 | 匹配测试的跟踪和饱和图；在模拟中演示碰撞感知选择 | 刚体动力学、优化、力控制和机器人专用工具 |
| 感知/本地化 | 传感器、校准、过滤、SLAM、规划接口 | 重现校准错误，评估一致的帧/时间处理，并报告传感器故障下的指标 | 多视图几何、概率机器人、鲁棒优化和真实数据集 |
| 自主/导航 | 移动模型、搜索、成本图、行为和恢复 | 构建一个模拟移动机器人来处理绕行、定位丢失和不可能的请求 | 更大的地图、交通协调、交互、性能和现场验证 |
| 机器人学习 | 演示、处理器、目标、闭环评估 | 使用匹配的重置来比较脚本化基线和学习策略，然后解释一个代表性故障 | 统计评估、强化学习、表征学习、模拟到真实和部署预算 |
| 嵌入式/现场 | 硬件接口、C++/时序、调试、可靠性 | 编写由时序跟踪、SIL/HIL 计划和监督程序支持的故障处理设计 | RTOS 内部结构、电气基础知识、安全工程、合规性和平台培训 |

一项有效的专业项目跨越一个相邻的界面。感知提供导航可以使用的带有时间戳的位姿；控制发布主管可以观察到的截止日期或执行器状态；数据集代码准确解释了哪些时钟和动作语义来自仿真器。

## 编写一个项目交接给其他人可以运行

使用小型存储库，而不是单独使用屏幕截图。第一页应该回答：你解决了什么问题？环境如何？什么命令运行基线？什么观察可以证明这一点？它明确没有表明什么？

保留紧凑的演示和测试矩阵。在模拟中显示正常行为、一次故意故障以及恢复或安全停止。包括运行时间、版本、重置/拆分选择、成功分母和至少一个失败跟踪。如果其他开发人员需要证书或物理实验室，请提供不需要访问它的固定装置或试运行路径。包括你认为最重要的权衡的简短决策记录。

### 在获取更多教程之前尝试复习练习

选择一个已完成的项目，并要求同行从干净的外壳中重现它。仅向他们提供存储库和自述文件。记录第一个有意义的结果和第一个不明确指令的时间。当他们完成后，改变一个限制——缺少观察、较低的速度限制或更严格的期限——并要求他们从你的合同中预测症状。修复阻止预测的文档或测试，然后在新环境中重复。

## 准备情况检查

你可以命名机器人的命令，但不能命名单位、限制、位姿来源或更新节奏。在进行更大的演示之前你应该改进哪些方面？

<details>
<summary>审查缺失的证据</summary>
<p>一次指定一个接口：生产者、消费者、数据类型、单位、帧、时域、更新期望和失败行为。在扩展演示之前演示经过验证的已知案例。</p>
</details>

一个作品集视频完美无缺，另一个则显示故障和修复。哪个是更强大的工程示例？

<details>
<summary>审查更有力的主张</summary>
<p>如果你显示准确的输入、诊断证据、更改的假设和回归测试，则修复后的案例通常会提供更多信息。也保留成功的结果，但不要忽略限制索赔的失败。</p>
</details>

## 使用本书作为基础

总会有另一个工具或子领域。旨在转移流程：制作一个小的正确模型，验证接口和假设，测试失败的地方，并使证据可重用。使用 [Modern Robotics](https://modernrobotics.northwestern.edu/nu-gm-book-resource/) 或 [Underactuated Robotics](https://underactuated.mit.edu/) 进行更深入的数学；用特定于版本的文档和物理系统的监督实验室工作来补充工具章节。
