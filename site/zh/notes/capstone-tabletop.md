## 为什么要分阶段建设这个系统？

困难的部分是如何让一个组件打印一条成功的消息。它在组装多个组件后解释证据。物理上合理的操作仍然可能是错误的，因为单位发生了变化，相机在重置之前进行了采样，或者策略是根据从未对其自身错误作出反应的观测结果进行评估的。在组合它们之前，在每个边界处建立一个已知良好的参考。

完成的项目对于从未启动过该项目的其他开发人员来说应该是可以理解的。给他们一份数据合同、一个练习带时间戳的 TF 的重放示例、一个仿真器基线和一份评估报告。丢失的工件比误导性的传递更能提供信息。如果跳过某个阶段，请命名缺少的运行时或接口，并记录仍需要哪些证据。

## 任务

在模拟中，从桌面上拾取一个块并将其放入目标区域。从脚本化基线开始，然后评估策略是否可以重现该任务。保持狭窄的接口：仿真器拥有物理特性，ROS 2 承载观测结果和命令，导出器构建演示，学习工具包使用导出的合约。你可以在 CPU 上运行 ROS 图，并使用另一台支持 Isaac Sim 的 GPU 计算机。

## Gate 1 — 在收集数据之前对齐重放

首先，[尝试时间戳实验室](/zh/demos/#clock-lab)。 [ROS 2回放章节](/zh/notes/ros2-bags-and-testing/)涵盖了心跳录制与回放。在这里你将添加标记的观测结果和 TF。这些脚本仅发布综合观测结果、变换和时钟；在所有终端中使用[隔离的 Jazzy shell 设置](/zh/notes/ros2-workspaces/)。

下载[跟踪发布者](/assets/labs/publish_tabletop_trace.py) 和[回放检查器](/assets/labs/check_tabletop_replay.py)。从下载目录运行以下命令，将两个终端保持在同一目录中。几秒钟的数据后停止记录器，然后停止发布器。重试时使用新的包目录。

```bash
# Terminal A
/usr/bin/python3 publish_tabletop_trace.py
# Terminal B
ros2 bag record --use-sim-time -o tabletop_fixture --topics /clock /tf /tabletop/observation
```

运行 `ros2 bag info tabletop_fixture` 以确认所有三个流都有消息。首先启动检查器，然后在检查器的 25 秒截止时间之前启动播放器：

```bash
# Terminal A
/usr/bin/python3 check_tabletop_replay.py --ros-args -p use_sim_time:=true
# Terminal B
ros2 bag play tabletop_fixture --clock 20
```

**预期：**`OK: 5 stamped poses transform to (2, 2) m`。重放播放器是唯一的时钟权威，检查器使用每条消息的标头标记而不是最新的转换。它专门针对该夹具的平面旋转和局部点。如果超时，请检查 `/tf` 上可用的图表可见性、包计数和时间戳间隔。请勿替代收货时间来使检查项通过。

在编写导出器之前编写捕获合约：

| 领域 | 合同示例 |
| --- | --- |
| 回合 | 唯一的回合ID；每次重置后的新ID |
| 时间戳 | 与回合相关的整数纳秒，一个时钟域；单独保留原始来源印章 |
| 状态 | 来自已保存清单的联合订单；旋转关节的弧度，棱柱关节的米 |
| 相机 | 识别的流、帧、校准、颜色顺序、形状和调整大小规则 |
| 命令 | 绝对手臂关节位置目标（以弧度为单位）；定义夹具目标单位并单独签名；不是扭矩或测量状态 |
| 配对 | 在采取行动之前捕捉观测结果；记录命令和采集标记；显式绑定倾斜并标记缺失数据 |
| 结果 | 成功、失败或超时；保留评估记录中的失败 |

**Pass:**确认每一集中的时间都在增加，标记和帧是可解释的，并且你可以将一个观测结果跟踪到其后面的确切命令行。

### 仅 CPU 合约检查

将[验证器](/assets/labs/check_trace.py)和[教学痕迹](/assets/labs/tabletop-trace.csv)下载到同一目录中。然后运行：

```sh
python check_trace.py tabletop-trace.csv
```

预期：`OK: 6 rows across 2 episodes`。尝试将一个指令时间戳移动到比其观察更早的位置或复制一帧编号；验证器应该失败。这是一个 CSV 夹具，**而不是 **真实记录或 LeRobot 数据集。它不验证图像内容、TF、单位或物理性质。如果时间戳被重写，故意的行移位仍然可以通过结构检查；使用 [对齐实验室](/zh/demos/#alignment-lab) 一起检查运动和标签。

## Gate 2 — 建立模拟基线

从[Isaac Sim场景章节](/zh/notes/isaac-scene/)中打包的Franka拾放场景开始。它的地平面是桌面抽象。在添加家具或定制机器人之前，让已发货的序列正常工作。在引入桥之前，在仿真器中调试控制器。

在运行前定义成功：例如，块在释放和稳定后，在时间预算内保留在目标区域中，没有不允许的接触。记录每个试验的种子、块启动位姿、场景和资产版本、步速、控制器配置、成功和失败阶段。保存一个短视频至少一次成功和一次失败。

**Pass:**报告所有预先声明的试验均取得成功，包括崩溃和超时。如果脚本控制器经常失败，请在收集培训演示之前调试触点、时序或控制器目标。

## Gate 3 — 导出、训练，然后评估

使用[LeRobot 数据章节](/zh/notes/lerobot-data/) 来规划映射，使用[训练章节](/zh/notes/lerobot-training/) 来运行版本化基线。 rosbag 不是 LeRobot 数据集。 Isaac Sim 数据仅通过明确支持的集成或生成预期密钥、形状、计时和操作约定的适配器到达 LeRobot。在没有该适配器的情况下，在其自己的数据集和兼容环境上训练和评估记录的 LeRobot 实验室；单独标记结果，而不是将其称为 Isaac-to-LeRobot。

1. 按 **片段或场景组**（而不是帧）保存训练/验证分割。在推理时保留相同的相机变换和特征顺序。
2. 过拟合一个小的训练子集来检查数据流；然后比较保留的行为并验证使用训练数据的标准化。
3. 如果你有匹配的闭环适配器，请在同一保留重置列表上运行策略和脚本基线。报告成功和分母、超时和安全停止计数以及常见故障的描述。如果只有离线验证，请报告离线损失并明确声明闭环成功未知。

**Pass:**另一个阅读器可以识别数据版本、拆分、策略检查点、仿真器版本、评估配置和结果分母。他们可以判断哪些工件是实际生产的，哪些步骤尚未验证。

<h2 id="cpu-mini-project-learn-why-a-replay-score-is-not-a-rollout-score">CPU 小项目：为什么回放得分不等于闭环评估得分</h2>

在连接 ML 策略之前，请隔离评估器。下载[单轴实验](/assets/labs/compare_policy.py)并运行`python compare_policy.py`。它是一个完整的教学模型，而不是弗兰卡物理或 LeRobot 检查点。一个位置描述一个对象；每个命令最多移动 0.25 个单位，恒定扰动每步减去 0.08 个单位。成功意味着 16 步后最终位置与目标的距离在 0.03 个单位以内。如果没有这样的视野和宽容，成功的衡量标准将会是模糊的。

该练习创建了三种训练重置的演示和三种不同重置的测试。每个演示行都包含一个预执行位置和剪辑的专家命令。它符合两个策略：

| 基线 | 可用输入 | 设计假设 |
| --- | --- | --- |
| 仅限时间 | 步进索引 | 如果所有演示看起来都很相似，那么记住的时间表可以与许多坚持的专家行动相匹配。它无法纠正不同的重置或新的干扰。 |
| 反馈意见 | 当前位置 | 它可以对状态错误采取行动。它仅使用未修剪专家命令的训练示例来估计恒定偏差。被剪裁的动作不能唯一地揭示专家的原始请求。 |

在运行之前阅读评估器。对于离线评分，两种策略都会看到专家的立场。离线度量是每集的平均绝对命令误差（以每步的位置单位为单位）。在推出过程中，每个策略都会看到其 **own**操作产生的头寸。仅时间策略将相同的命令列表应用于所有三个重置，因此任何初始位置差异仍然存在：简化的动态在每次重置中添加相同的增量。当反馈策略观察到偏差时，它可以发出不同的命令。

1. **Predict.**如果平均训练重置为 0.10，则决定哪个保留的重置应在仅时间计划下完成最接近目标。
2. **运行实验。**仅时间策略的离线误差很小，但它错过了所有三个最终容差。反馈策略在这三个方面都取得了成功。检查终端位置而不仅仅是总量。
3. **更改一个变量。**将 `TOLERANCE` 扩大到 0.06。底层动作质量和终端位置不变；两次仅限时间的试验现在算成功。在比较不同的策略之前先放回容差。
4. **提出有限制的声明。**支持“在这三个重置上保持目标的反馈”。 “反馈将在看不见的硬件上成功”并非如此。微型确定性夹具测试评估代码，而不是性能保证或物理系统。

将同样的区别转移到桌面上。比较一项策略的保留行动错误和推出结果，而不将它们合并为一个分数。在与脚本基线的第一个偏差周围保存一个短窗口。询问策略在不匹配之前是否看到了有效的观测结果，以及两项策略是否具有相同的操作限制。

## 提供可重复的切换

实验目录示例：

```text
run/
  manifest.json        environment and artifact revisions; tested or skipped gates
  replay/              recording metadata, or durable URI plus checksum
  simulator/           scene version, controller config, seeds, trial outcomes
  dataset/             episode membership, feature and action semantics
  evaluation/          policy reference, metrics with denominators, failed trials
```

让大数据远离源代码控制。保留引用和校验和，以便其他开发人员可以恢复确切的工件，而不仅仅是另一个同名的文件。在评论中，要求读者选择一个片段，并从原始观察到导出样本再到度量进行追踪。如果他们无法重现该链，请首先改进来源，而不是重新运行所有内容。

### 从第一次错误测量开始诊断

| 第一次不良观察 | 最窄的下一个实验 |
| --- | --- |
| 位姿出现，但查找其标头标记失败 | 在禁用机器人运动的情况下比较缓冲间隔和时钟发布者。 |
| 回放是正确的，但是立方体随着脚本控制器滑动 | 独立于数据集检查仿真器中的接触和夹具状态。 |
| 脚本化试验通过，但导出的标签领先图像一控制步 | 检查重置周围和已知夹具转换处的配对。暂时不要重新训练。 |
| 离线错误率低，但只有推出失败 | 比较轨迹分歧、动作缩放以及故障是否发生在训练观察之外。 |

## 自检

模型的离线动作误差较低，但在提升后会掉落方块。在增加模型容量之前你会调查什么？

<details>
<summary>检查你的答案</summary>
<p>检查围绕接触、动作单元和夹具约定、观察预处理和闭环计时的时间戳配对。将相同的试验与脚本控制器进行比较，并检查训练集是否覆盖了故障状态。仅离线错误并不能验证恢复或稳定性。</p>
</details>

## 转移练习：选择一个可以回答问题的比较

第一个策略适用于简单的中心重置，第二个策略适用于较难的边缘重置。其结果是 8/10 与 6/10。这足以对策略进行排名吗？

<details>
<summary>检查比较设计</summary>
<p>不会。策略在重置分配的同时发生了变化。对这两项策略重复使用一个预先声明的重置列表，保持容差和范围固定，并保存每次重置的结果。即使总体成功没有改变，失败类别也可以解释第二个策略在哪些方面有帮助。</p>
</details>

## 弘扬什么

- 在集成策略之前证明采集时间、帧语义和数据流。
- 使用最简单的独立基线，可以证伪你的假设；使适配器经过深思熟虑且可测试。
- 分别报告离线拟合和闭环行为。发布你实际跑过的阶段的证据。
