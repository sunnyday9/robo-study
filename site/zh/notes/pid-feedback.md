## 为什么目标不是命令

如果你的应用程序要求模拟关节达到 1 弧度，则物理输入可能是扭矩，而不是位置。在固定时间内施加固定扭矩假定关节完全具有你预测的惯性、摩擦力和初始状态。一旦负载发生变化，开环命令就不再给出相同的结果。反馈衡量发生的情况并使用错误来决定下一步做什么。

我们的目标是实现一个可测量的、有界的实验：对于一个玩具系统，将三个控制器与相同的目标和干扰进行比较，然后使用迹线来解释权衡。我们没有找到硬件方面的收益。真实的手臂可能已经具有内部循环和限制，并且将位置接口视为扭矩接口是不同的控制器，而不是不同的调整。

```text
desired ──▶ error ──▶ PID law ──▶ output limits ──▶ plant
            ▲                                     │
            └──────────── subtract measurement ◀──┘
```

控制器看到的是错误，而不是整个被控对象。应用的命令可能与其请求不同。记录两者：否则，当执行器已经达到极限时，你可能会将缓慢的运动归因于较小的增益。

## 基本原理

反馈控制器测量当前输出并将其与目标进行比较。将错误定义为 `target − measurement`。 PID 控制器结合了当前误差、累积历史记录及其变化率。对于固定采样间隔：

```text
integral = previous_integral + error × dt
slope    = (error − previous_error) / dt
command  = Kp × error + Ki × integral + Kd × slope
```

在进行一阶导数之前，将先前的误差初始化为第一次测量的误差。离散导数会放大测量噪声；此练习的增益不是真实硬件的设置。

| 期限 | 有用的直觉 | 出了什么问题 |
| --- | --- | --- |
| P | 电流误差越大，修正量越大。 | 设备可能需要持续的非零命令，仅在 P 下留下稳定的偏移量。 |
| I | 即使当前误差变为零，也可以存储过去的误差以进行修正。 | 当输出被削波并延迟恢复时，累积项可能会增长。 |
| D | 对变化的方向和速度做出反应。 | 区分噪声数据会放大快速变化。突然的目标变化可能会导致微分误差时出现微分冲击。 |

离散更新需要明确的时基。当环路速率变化时，从积分或微分中去掉 `dt` 会使有效增益发生变化。如果计时器有抖动，请测量实际间隔或设计循环，以便其计时受到良好限制。选择相同的参考和测量单位，记下输出限制，并定义重置时会发生什么。在许多应用中，对测量结果而不是误差进行微分可以避免仅由设定点跳跃引起的大导数。

## 算例

在使用归一化单位的仿真中，令当前误差为 `0.2`，先前误差为 `0.3`，先前积分为 `0.1`。对于 `dt = 0.1 s`，更新后的积分为 `0.12`，斜率为 `−1`。 `Kp = 2`、`Ki = 0.5` 和 `Kd = 0.1` 的增益得出：

```text
2 × 0.2 + 0.5 × 0.12 + 0.1 × (−1) = 0.36
```

如果执行器最多接受 `0.3`，则应用的命令为 `0.3`。单独剪切命令并不能阻止积分的增长。如果错误不断将命令推向极限，则累积的错误可能会延迟恢复。这是积分饱和。

## 开发流程：比较同一被控对象的控制器

使用标准化的一态教学被控对象：`dy/dt = -y + applied - 0.15`。消极项模拟了衰退的趋势； 0.15 是一个恒定的扰动。目标是 `y = 0.5`，命令被限制为 ±0.8。将目标保持在平衡状态需要 `applied = 0.65`（在限制范围内）。在进行任何调整之前，此可行性检查会告诉你控制器可以达到目标。

将以下内容保存为 `compare_control.py` 并使用 Python 3 运行它。它仅对该被控对象进行建模并使用欧拉积分；它不会在进程之外发送命令。

```python
TARGET, LIMIT, DISTURBANCE, DT = 0.5, 0.8, 0.15, 0.02


def trial(integral_gain, anti_windup):
    measurement = integral = 0.0
    saturated = 0
    peak = measurement
    for step in range(600):
        error = TARGET - measurement
        candidate = integral + error * DT
        requested = 3.0 * error + integral_gain * candidate
        presses_limit = (requested > LIMIT and error > 0) or (requested < -LIMIT and error < 0)
        if not anti_windup or not presses_limit:
            integral = candidate
        requested = 3.0 * error + integral_gain * integral
        applied = max(-LIMIT, min(LIMIT, requested))
        saturated += requested != applied
        measurement += DT * (-measurement + applied - DISTURBANCE)
        peak = max(peak, measurement)
        if step in (0, 49, 149, 599):
            print(f"t={(step + 1) * DT:5.2f} y={measurement:.3f} "
                  f"requested={requested:.3f} applied={applied:.3f}")
    print(f"final error={TARGET - measurement:.3f}, "
          f"overshoot={max(0.0, peak - TARGET):.3f}, clipped ticks={saturated}")


for name, gain, guard in (("P", 0.0, False), ("PI", 4.0, False), ("guarded PI", 4.0, True)):
    print(name)
    trial(gain, guard)
```

首先预测仅 P 稳态。初始命令饱和，但当循环在 `y = 0.338` 附近达到平衡时，命令不再受限：`0 = -y + 3(0.5-y) - 0.15`，因此 `y = 1.35/4`。你现在可以解释残差，而不必归咎于软件错误。 PI 可以在其积分状态下传送稳定命令，但在此示例中，积分也会在饱和期间开始累积。当提议的更新将进一步达到极限时，受保护的变体将保留积分。它仍然可以朝着解除限制的方向整合。

比较最终误差、峰值超调（高于目标的最大量）和截断的控制步。哪些指标发生变化以及原因？控制器不会因为最小化一个数字而自动变得更好。如果过冲意味着击中模拟接触面，则较慢的方法可能是合适的。比较控制器时，保持对象、初始条件和限制固定，以便你可以解释变化。

| 控制器 | 最终误差（四舍五入） | 峰值超调 | 削减了 600 个控制步 |
| --- | ---: | ---: | ---: |
| P | 0.163 | 0.000 | 23 |
| PI | 大约 0 | 0.079 | 106 |
| 受保护的PI | 大约 0 | 0.000 | 23 |

在此运行中，尽管设备已达到 0.413，但无防护的 PI 控制器仍将限制控制在 1 秒。 3 秒时，它已越过目标。保护控制器在饱和后恢复正常积分，因此它仍然补偿干扰而没有相同的存储误差。这个结果取决于所选择的被控对象和收益；它并不能证明受保护的 PI 永远不会超调。

![三个实验室检查点的位置：P 稳定在 0.5 以下，PI 超调，受保护的 PI 接近 0.5，在此运行中没有超调。](/assets/pid-response.svg)

三个检查点均匀分布是为了比较，而不是按时间比例。线连接采样点；结果表中的峰值是在每个模拟步骤中测量的，不需要出现在显示的检查点处。

## 调试下一个实验

| 症状 | 调音前检查 |
| --- | --- |
| 所有控制器都远低于目标值 | 计算稳定命令并检查应用的限制。将 `LIMIT` 更改为 0.6 并预测会发生什么。 |
| 目标更改后第一次更新的巨大输出 | 检查导数输入、先前值和时间间隔。实验室比较了 P 和 PI 以隔离饱和。 |
| 降低更新频率后响应变差 | 在增加增益之前检查是否缺少 `dt`、离散化错误或反馈延迟。 |
| 命令向正确的方向变化，但状态向相反的方向变化 | 检查执行器符号、坐标约定以及你正在测量的响应。 |

如果稍后添加测量噪声，请保持种子和噪声幅度恒定。比较控制信号以及跟踪曲线；模型可以在快速改变其应用命令的同时看起来平滑。首先测量，改变一件事，然后重复。

## 转让练习：可行性先于收益

输出限制更改为±0.6。你的同事建议将 `Ki` 加倍以最终保持目标。你告诉他们什么？

<details>
<summary>检查可行性论证</summary>
<p>在目标上，玩具厂需要应用 0.65 的命令。任何增益都无法克服 0.6 的上限，完全正命令时的最佳稳态为 0.45。更多的积分增益可以在不改变应用值的情况下使请求增长。报告饱和度并重新考虑目标、驱动极限或被控对象设计。</p>
</details>

## 弘扬什么

- 设定点说明你想要什么；被控对象决定应用的命令如何改变状态。
- 分别记录请求和应用的命令。在将稳定误差归因于调整之前测试执行器的可行性。
- 在相同的启动条件下比较控制器并一次解决一种故障机制。
